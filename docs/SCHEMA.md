# Data schema — `data/hexagrams.json`, `data/trigrams.json`

This is the contract between the Phase 1 build (`scripts/`) and the site (Phases 2–4).
Normative conventions (bits, labels, Legge slot map) are stated in
[PLAN.md](PLAN.md); they are repeated here only where the JSON shape depends on them.

Both files are UTF-8 JSON, pretty-printed with 2-space indent and a trailing newline,
array order fixed (King Wen order / trigram table order). They are generated by
`node scripts/build.mjs` and checked by `node scripts/validate.mjs --require zh,legge`
(`poem` is added to the gate in Phase 4). Never hand-edit them — fixes go through
`scripts/overrides.json` (see [Build inputs](#build-inputs-committed)).

## `data/trigrams.json`

Array of 8 objects, in this order: 乾 坤 震 巽 坎 離 艮 兌.

| field | type | meaning |
|---|---|---|
| `name_zh` | string | Trigram name, e.g. `"乾"`. Primary key; `hexagrams.json` refers to trigrams by this string. |
| `name_pinyin` | string | Hand-checked pinyin with tone marks, e.g. `"Qián"`. |
| `name_en` | string \| null | English name authored by us in Phase 4. `null` in Phase 1. |
| `symbol` | string | Unicode trigram character, e.g. `"☰"` (U+2630–U+2637). |
| `image_zh` | string | Natural image, e.g. `"天"`. One of 天地雷風水火山澤. |
| `image_pinyin` | string | Pinyin of `image_zh`, e.g. `"Tiān"`. |
| `bits` | [0\|1, 0\|1, 0\|1] | Lines bottom→top; yang = 1. |

| name_zh | name_pinyin | symbol | image_zh | image_pinyin | bits (bottom→top) |
|---|---|---|---|---|---|
| 乾 | Qián | ☰ | 天 | Tiān | `111` |
| 坤 | Kūn | ☷ | 地 | Dì | `000` |
| 震 | Zhèn | ☳ | 雷 | Léi | `100` |
| 巽 | Xùn | ☴ | 風 | Fēng | `011` |
| 坎 | Kǎn | ☵ | 水 | Shuǐ | `010` |
| 離 | Lí | ☲ | 火 | Huǒ | `101` |
| 艮 | Gèn | ☶ | 山 | Shān | `001` |
| 兌 | Duì | ☱ | 澤 | Zé | `110` |

Example:

```json
{
  "name_zh": "乾",
  "name_pinyin": "Qián",
  "name_en": null,
  "symbol": "☰",
  "image_zh": "天",
  "image_pinyin": "Tiān",
  "bits": [1, 1, 1]
}
```

## `data/hexagrams.json`

Array of 64 objects in King Wen order (`number` 1…64 increasing).

| field | type | meaning |
|---|---|---|
| `number` | integer 1–64 | King Wen number, from the independent lookup table below. Never derived from `bits`. |
| `name_zh` | string | Chinese hexagram name in traditional characters, e.g. `"既濟"`. 1–2 characters (習坎/重離 are *not* names; 29 is 坎, 30 is 離). |
| `name_pinyin` | string | Hand-checked pinyin with tone marks (table below). Syllables separated by a space, first letter capitalized. |
| `name_en` | string \| null | English name/title authored by us as part of the rendering voice (Phase 4). `null` in Phase 1 — UI leads with Chinese + pinyin until then. |
| `symbol` | string | Unicode hexagram character U+4DC0 + number − 1 (䷀…䷿), King Wen order. |
| `bits` | [0\|1 ×6] | Lines bottom→top (index 0 = bottom), yang = 1. Equals lower-trigram bits ++ upper-trigram bits. |
| `lower` | string | `name_zh` of the lower (inner) trigram. |
| `upper` | string | `name_zh` of the upper (outer) trigram. |
| `texts` | object | Keyed by translation id: `zh`, `legge` (and `poem` from Phase 4; the key is absent until the hexagram's rendering lands). |

Each `texts.<id>` object has exactly these slots:

| slot | type | meaning |
|---|---|---|
| `judgment` | string[] | 卦辭. Non-empty. |
| `image` | string[] | 大象 (象傳). Non-empty. |
| `lines` | string[][] (length 6) | 爻辭, bottom→top. `lines[0]` is line 1. Each element non-empty. Line labels (初九…) are **not** included — generate them from `bits` + position via the label table in PLAN.md. |
| `special` | string[] \| null | 用九 (hexagram 1) / 用六 (hexagram 2). `null` for the other 62. |

Text-slot rules:

- Every slot is an **array of display lines** (strings). For `zh` and `legge` each slot
  currently has exactly one element (one paragraph); `poem` will use several (verse
  lines). Elements never contain `\n`. Renderers join `poem` elements with line breaks;
  single-element slots render as one paragraph.
- `zh`: traditional characters with Project Gutenberg #25501's punctuation. Prefixes
  stripped: judgment has no `坎：`-style name prefix, image has no `象曰：`, lines have
  no `初九：`, special has no `用九：`. Note hexagram 29's judgment therefore begins
  `習坎，…` and 30's image/lines keep their text as printed.
- `legge`: Legge's wording verbatim, including his parentheses and his line preambles
  ("In the first line, divided, …"). Only mechanical normalization is applied:
  dehyphenation across print line breaks, whitespace collapsing, removal of the printed
  paragraph numbers (`1. `…`7. `) and of the roman-numeral prefix on the Great Image.
  Character-level OCR corrections are applied via `overrides.json`, each with a reason.
  One deliberate transcription policy: Legge's romanization **diacritics are normalized
  to plain letters** (Khwăn→Khwan, Hsü→Hsu, Kî Zî→Ki Zi, Lü→Lu). The IA OCR drops or
  garbles the marks inconsistently, and plain letters keep hexagrams 33–64 (which have
  no proofread collation) consistent with 1–32 without guessing marks. Garbled name
  spellings restored under this policy are individual `overrides.json` entries.
- No slot contains markup (`-{`, `{{`, `[[`, HTML), and script purity holds: `zh` slots
  contain no Latin words; `legge` slots contain no CJK characters.

Example (abbreviated; hexagram 1 as shipped in Phase 1):

```json
{
  "number": 1,
  "name_zh": "乾",
  "name_pinyin": "Qián",
  "name_en": null,
  "symbol": "䷀",
  "bits": [1, 1, 1, 1, 1, 1],
  "lower": "乾",
  "upper": "乾",
  "texts": {
    "zh": {
      "judgment": ["元，亨，利，貞。"],
      "image": ["天行健，君子以自強不息。"],
      "lines": [
        ["潛龍，勿用。"],
        ["見龍在田，利見大人。"]

      "special": ["見群龍無首，吉。"]
    },
    "legge": {
      "judgment": ["Khien (represents) what is great and originating, penetrating, advantageous, correct and firm."],
      "image": ["Heaven, in its motion, (gives the idea of) strength. The superior man, in accordance with this, nerves himself to ceaseless activity."],
      "lines": [
```

`validate.mjs` checks that. Bits strings below are bottom→top.

## Build inputs (committed)

- `scripts/provenance.json` — pins every external source: for each input file, its URL,
  cache filename, SHA-256, and (for Wikisource) per-page revision ids (`oldid`s), plus
  human-readable edition notes. Default builds verify cached files against this
  manifest and fail on mismatch. `node scripts/build.mjs --fetch` (re)downloads
  everything and rewrites the manifest; that is the only mode that touches the network
  when a cache already exists.
- `scripts/overrides.json` — post-parse corrections, applied in order. Each entry:
  `{ "slot": "legge.29.lines.2", "find": "…", "replace": "…", "reason": "…" }` for a
  substring fix (`find` must occur exactly once in the slot's joined text or the build
  fails), or `{ "slot": "zh.3.lines.2", "value": ["…"], "reason": "…" }` to replace a
  whole slot. Slot paths are `<translation>.<number>.<judgment|image|special>` or
  `<translation>.<number>.lines.<0-5>` (0-based). Every entry needs a `reason` citing
  its evidence (scan reading, collation source, or editorial rule).

Downloads live in `scripts/.cache/` (gitignored). The build is deterministic: no
timestamps in outputs, fixed key/array order; re-running it produces byte-identical
`data/*.json` (verify with `git status`/`git diff`).

## Phase 4 extension (for reference)

Phase 4 adds `texts.poem` with the same four slots (multi-element verse arrays), fills
`name_en` on hexagrams and trigrams, and raises the validation gate to
`--require zh,legge,poem`. Poem sources are authored in `data/poem/NN.json` and merged
by the build; the merged shape is exactly the `texts.poem` object above.
